# 工作流程

把來源內容改寫成可直接交給 `audio` skill 的單人獨白 `.txt` 腳本。

## 輸出格式

固定使用 `[說書人]`，一段一行，段落間空行：

```text
[說書人] 今天要說的是一件關於 AI 如何改變軟體開發的事。

[說書人] 這件事大概從兩三年前開始發酵。
```

## 寫作風格

- 像真人平穩敘述，不像朗讀文章。
- 不使用戲劇化套語，例如「話說」「且聽下回」「列位看官」。
- 不把自己當第二個說話者，不用「各位聽眾」「你們覺得呢」。

## 改寫規則

- 去掉 emoji、URL、`@mention`、hashtag 與不適合朗讀的 Markdown。
- 長句拆短，少用逗號；能自然斷句就用句號。
- 數字與單位改成口語讀法，例如 `$0.08/hr` → 「一小時零點零八美元」。
- 英文專有名詞保留原文，例如 Anthropic、Claude、RAG、API。
- 用「其實」「值得注意的是」這類銜接詞時要克制，避免口頭禪。
- 開頭要引入主題，結尾要收束。

## 長度策略

- 預設 6~8 分鐘；短內容 4~6 分鐘；長內容 8~10 分鐘。
- 除非使用者明確指定，最終音訊不得超過 10 分鐘。
- 長影片或長文章不要逐段翻譯，改做高密度整理：保留主線、轉折、關鍵例子與結論。
- 主題數以 3~5 個為原則；超長內容應拆成多集。

## 操作步驟

1. 讀取來源內容。
2. 萃取 3~5 個邏輯段落。
3. 寫成 `[說書人]` 獨白腳本。
4. 輸出 `script_<日期>.txt`，除非使用者指定檔名。
5. 告知下一步可用 `audio` skill 生成 mp3。
